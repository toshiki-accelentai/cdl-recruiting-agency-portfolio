## Architecture

### Assistant routing

`POST /webhook/cdl/assistant-request`

- Normalizes the inbound caller number to E.164.
- Searches Zoho Recruit and selects the existing- or new-candidate VAPI
  assistant.
- Fails open to the new-candidate assistant when Zoho is unavailable, avoiding
  a dropped inbound call.

### Applicant intake

`POST /webhook/cdl/log-applicant`

- Validates the VAPI tool contract and normalizes name, phone, location,
  experience, readiness, and urgency.
- Preserves the caller's actual experience amount (for example, `5+ years` or
  `18 months`) before converting it to Zoho Recruit's numeric
  `Experience_in_Years` field; it does not collapse all senior drivers into a
  `2+ years` bucket.
- Searches Zoho by phone, then creates or updates the Candidate.
- Adds the intake Note and calls Calendar Booking through n8n's native Execute
  Sub-workflow node; the booking workflow has no public webhook.
- Returns an explicit VAPI result for validation failures, Zoho failures,
  unavailable slots, calendar failures, and successful bookings.
- Records the booking outcome as a Zoho Note after responding to VAPI.

### Calendar booking

Internal subworkflow contract: one normalized/saved Candidate object in, one
booking-result object out.

- Validates Pacific business hours and US federal holidays.
- Calls Google Calendar FreeBusy before attempting the write.
- Uses a deterministic Google event ID based on the 15-minute UTC slot. Google
  therefore acts as the atomic uniqueness constraint when two callers race for
  the same slot.
- Embeds `vapiCallId` and `zohoCandidateId` in private event properties and
  reads the event back before reporting success. A caller is confirmed only if
  the stored event owner matches that VAPI call.
- Restores cancelled slot tombstones with an `If-Match` ETag. This preserves
  atomic locking while allowing a cancelled slot to be reused.
- Retries of the same call are idempotent; a competing call receives
  `slot_unavailable`, never a false confirmation.

### Post-call reporting

`POST /webhook/cdl/post-call`

- Acknowledges VAPI immediately.
- Finds the Candidate by the exact Zoho Candidate ID returned by Intake, with
  normalized-phone search as a fallback. Direct-record requests never receive
  search-only query parameters.
- Stores summary, transcript, readiness, lead temperature, experience,
  duration, end reason, and itemized call cost in a Zoho Note.
- Names that Note `AI Call Summary & Full Transcript — <call ID>` so recruiters
  can distinguish it immediately from the structured `VAPI Intake` Note.
- Adds a clearly labelled per-call postcode section containing ZIP, ZIP prefix,
  city/state, and basic US ZIP-format validation. This is a Candidate-level
  artifact, not an aggregate geographic dashboard or external geocoding result.
- Correlates the report with the exact Zoho Candidate ID returned by the intake
  tool, with phone lookup retained only as a fallback. This avoids losing or
  misattaching a report while Zoho's phone-search index is still updating.
- Converts an asynchronous Note-write failure into a failed n8n execution so
  it appears in error history instead of disappearing silently.

Zoho Recruit is the system of record. Airtable, Gmail, Azure OpenAI, manual
OAuth-token nodes, and LLM classification are not dependencies.

## Reliability and privacy policy

- Zoho and Google calls use a 10-second timeout, up to three attempts, and a
  one-second retry interval.
- Expected business failures return explicit typed results. Unexpected
  asynchronous persistence failures fail the n8n execution.
- Error executions are retained. Successful executions are not retained to
  reduce duplicate storage of applicant PII; durable records live in Zoho.
- Execution-progress persistence is disabled because these workflows have no
  Wait/resume nodes.
- `callId`, Candidate ID, and Calendar event ID provide correlation across
  workflow boundaries.
- Publish order is Booking first, then Intake, Routing, and Post-Call.
  Deactivation order is the reverse so Intake never references an unavailable
  subworkflow.

walkthrough:

- Zoho Candidate ID: `870474000000581004`
- Location: Vancouver, WA 98660
- Experience: 2 years; readiness: within 7 days; source: Phone Call
- Notes: `VAPI Intake — loom-demo-candidate-20260812` and
  `Callback — loom-demo-candidate-20260812`

The callback request deliberately uses a Saturday. This demonstrates the
business-hours fallback and does not create a Google Calendar event. Find the
record in Zoho Recruit by its name or phone number. To verify it without
changing it:

```powershell
python scripts\seed_zoho_loom_candidate.py --verify-only
```

The seed command is dry-run by default and uses `--apply` for an intentional
create/update. `scripts/delete_zoho_note.py` is also dry-run by default and is
limited to deleting one exact known Note ID for test-artifact cleanup.

## Google OAuth note for self-hosted n8n

The connected credential is `Google Calendar account`. Self-hosted n8n requires
a Google Cloud OAuth client of type **Web application**, with this exact
authorized redirect URI and no trailing slash:

`https://n8n.accelentai.com/rest/oauth2-credential/callback`

If an External OAuth app remains in Testing, its Calendar refresh token expires
after seven days. Use an Internal app when available or publish the External app
before production.

## Build, deploy, and verify

```powershell
python scripts\build_modular_workflows.py --booking-workflow-id nIqItEX8Vbn78sWo
python -m unittest discover -s tests -p "test_*.py"
node tests\js\test_cdl_helpers.js
python scripts\deploy_n8n_suite.py
python scripts\deploy_n8n_suite.py --apply
python scripts\smoke_test_modular_suite.py
```

The deploy command is dry-run unless `--apply` is supplied. Even with
`--apply`, it creates or updates inactive drafts and never publishes them. The
smoke suite temporarily publishes only the components under test, exercises
routing, invalid intake, post-call acknowledgement, native subworkflow booking,
same-slot cancellation restoration, and calendar cleanup, then returns every
component to inactive.
